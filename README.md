# TrueFrame — AI image & video detector

Drag and drop a photo or video and TrueFrame estimates whether it was generated by AI, then
explains why in plain English. Everything runs in the browser: files are never uploaded.

![layers](https://img.shields.io/badge/detection_layers-6-5b4bdb) ![privacy](https://img.shields.io/badge/runs-100%25_in_browser-2a78d6)

## Run it

- **Windows:** double-click `start.bat`. It serves the folder on <http://localhost:8000> and opens it.
- **Any OS:** `python -m http.server 8000` in this folder, then open <http://localhost:8000>.
- **Hosting:** it is a static site. Upload the folder to GitHub Pages, Netlify, Vercel, S3, etc.

Opening `index.html` directly from disk also works, but it is noticeably slower: the browser can't
cache the neural models, and workers and multi-core inference are unavailable from `file://`.

### Hosting on GitHub Pages

Push this folder to a repository, then *Settings → Pages → Deploy from a branch* (root folder).
The empty `.nojekyll` file tells Pages to serve the files as they are.

The site itself is under 0.5 MB. The neural models (117 MB in the default *Standard* mode,
60 MB in *Light*) are **not** stored in the repository: browsers fetch them from the Hugging Face
CDN. That keeps the repository far below GitHub's 100 MB file limit and the site far below the
Pages bandwidth limit (100 GB a month), and the CDN is fast worldwide.

**Why the models run in your browser, not on a server:** GitHub Pages only serves static files —
it cannot run code. A separate inference server would also mean uploading every file people
check, which is exactly what TrueFrame promises not to do. Instead, the in-browser pipeline is
tuned to be fast on ordinary laptops (see below).

### Speed

On a 4-core laptop (Intel i7-10510U) a 10-megapixel photo takes about 5 s instead of 14 s:

- **All cores** — `sw.js` is a tiny service worker that adds the two headers
  (`Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy`) GitHub Pages cannot send. They
  make the page *cross-origin isolated*, which lets the neural networks use several CPU cores:
  ~3× faster per model, same scores. On the very first visit the page reloads itself once to
  switch this on. It caches nothing, so site updates appear normally.
- **Everything at once** — the two networks each run in their own Web Worker and start as soon as
  the image is decoded; the pixel forensics run in a third worker at the same time, and
  error-level analysis on the page meanwhile. Video frames go to the networks as each one is
  decoded. The page itself stays responsive throughout.
- **No wasted work** — each network looks at the image once (a mirrored second look was measured
  to add nothing), and a spectrum only used by a disabled check is no longer computed. All
  forensic measurements are bit-for-bit identical to before.
- **GPU (WebGPU) tested and rejected** — on integrated graphics it was barely faster than the
  multi-core CPU path, and one model's scores drifted, which would have hurt accuracy.

### Model download

- **4-bit weights** — 117 MB instead of 180 MB for the 8-bit versions, with practically the same
  accuracy (see the table below).
- **Early start** — on a fast connection the models start downloading quietly once the page is
  idle; otherwise as soon as you hover the drop zone or drag a file. The pill in the header shows
  their status.
- **Cached for next time** — files are pinned to a model revision and kept in the browser's
  Cache Storage (persistent storage is requested where the browser allows it without a prompt),
  so later visits load them from disk in a few seconds.
- **Connections opened early** — `preconnect` hints for the CDNs and a `modulepreload` for the
  runtime; web fonts no longer block the first paint.

The gear icon lets you pick *Light* (one model) or *Off* (metadata and forensics only), and turn
background downloading off.

## How detection works

Each check turns what it finds into a **log-likelihood ratio** — how much more often that
observation occurs in AI images than in real ones. The ratios are summed per layer, each layer is
capped so one family of correlated checks cannot dominate, and the total becomes the probability
shown on the gauge, with a confidence level and a summary of the strongest reasons.

| Layer | What it looks at | Strength |
|---|---|---|
| **Provenance & AI labels** | C2PA Content Credentials (JUMBF boxes, CBOR claims, actions, signer certificates), IPTC `DigitalSourceType` (e.g. *trainedAlgorithmicMedia*), generation settings written by Stable Diffusion / ComfyUI / InvokeAI / NovelAI / Fooocus / Midjourney, AI tool names in software fields | Decisive when present |
| **Neural networks** | Two open-source detectors (Swin "SMOGY" and ViT-Base) run locally via Transformers.js/ONNX, on the image and its mirror. Combined with weights fitted by logistic regression | Strong |
| **Frequency analysis** | 2-D FFT of the high-pass residual over several tiles; looks for the regular 8-pixel peak grid left by the 2× upsampling layers of generator decoders, self-calibrated against control frequencies. Skipped for JPEG-style files and files with JPEG history | Specific, modest |
| **Camera-sensor forensics** | Bayer colour-filter-array demosaicing traces (green quincunx prediction-error contrast and its consistency across blocks); consistency of sensor noise across flat regions (Immerkær estimator) | Strong for camera originals |
| **Metadata & file traits** | Camera make/model/exposure/MakerNote/GPS, phone-camera XMP, native generator resolutions vs. sensor resolutions, download file-name patterns, JPEG quantisation tables, editing software, screenshots, social-platform re-encoding | Weak–moderate |
| **Video structure** | MP4/MOV box parser (Apple/Android/Samsung/Sony/GoPro/… recording tags, GPS, encoder, audio track, frame rate), WebM/EBML parser, plus neural scores of ~10 frames sampled across the clip | Moderate |

## Using the site

- **Live analysis:** while a file is checked you see each step complete, a running AI-likelihood
  gauge that moves as evidence arrives, the findings as they are made, and the forensic views as
  they are computed — plus the model download with its speed and time left, and rotating facts
  about how AI images are detected.
- **Your guess:** pick *Real* or *AI* while you wait; the verdict lands on the image as a stamp
  and tells you whether you called it.
- **Evidence tug-of-war:** every finding is a block pulling towards *real* or *AI*; longer blocks
  are stronger. Click one to jump to the explanation.
- **Score builder:** switch any detection layer off and the verdict recomputes instantly, with a
  chart of how the score builds up layer by layer.
- **What we found:** filter findings (points to AI / points to real / context), switch between a
  *Simple* and a *Detailed* view (with likelihood factors and technical notes), and jump from a
  finding straight to the matching forensic view.
- **Forensic lab:** compare the original with the error-level or noise map using a draggable
  slider, an opacity overlay or side by side; magnify any spot 3×; hover the frequency spectrum to
  read repeat periods and overlay where generator peaks would sit. For videos, inspect every
  sampled frame, its score, and play the clip from that moment.
- **Metadata explorer:** searchable, grouped metadata with one-click copy.

## Accuracy — read this

Measured on a labelled set (see `assets/js/engine/calibration.js` for details and
`tests/README.md` to run your own):

54 AI images from Midjourney v5/v6.1, SDXL, DALL·E 3, GPT-image-1, GPT-image 4K, Nano Banana Pro,
FLUX.2 and a text-rendering set; 44 camera/phone originals (Canon, Nikon, Sony, Fujifilm, Olympus,
Panasonic, Samsung, Apple, HTC, DJI…); 11 AI videos (Sora, Veo, Kling, Wan, CogVideoX) and
9 real videos. Default *Standard* neural mode.

| Test condition | AUC | AI images flagged as AI | Real photos wrongly flagged as AI |
|---|---|---|---|
| Original files | 1.00 | 53 / 54 (22 confirmed by embedded provenance) | 0 / 49 |
| Same pixels, all metadata removed | 0.99 | 48 / 54 | 1 / 44 |
| "Web copy": 1280 px, JPEG quality 85, no metadata | 0.95 | 44 / 54 | 3 / 44 |
| Half-size PNG, no metadata | 0.96 | 47 / 54 | 2 / 44 |
| Videos | 0.97 | 10 / 11 (2 Sora clips confirmed by C2PA) | 0 / 9 |

Measured with the shipped configuration (4-bit models, one view per image). Compared with the
earlier 8-bit, two-view setup — a 54 % larger download and 3× slower — re-compressed copies lose
two AI catches and gain one fewer false alarm; the other rows are unchanged or better.

Files not flagged either way are reported as **Inconclusive** rather than forced into a verdict.

**Be careful with these numbers.** The set is small, and the same generators were used to set
the thresholds, so real-world accuracy will be lower — especially for generators released after
the neural models were trained.

What these numbers mean in practice:

- **Files straight from an AI tool** are usually caught with certainty, because most major
  services now embed Content Credentials or IPTC labels.
- **Re-shared copies** (screenshots, social media, messaging apps) lose those labels. The verdict
  then rests on the neural networks and pixel forensics, which are good but not infallible.
- **Brand-new generators** can fool the neural networks until detectors are retrained.
- A "real" verdict is not proof of authenticity: a real photo can still be misleading, edited or
  taken out of context.

## Project layout

```
index.html                 page
sw.js                      service worker: cross-origin isolation for multi-core inference
assets/js/coi.js           registers sw.js (first visit reloads once)
assets/css/app.css         styles (light theme)
assets/js/engine/          detection engine (no dependencies)
  core.js                  utilities
  fft.js                   radix-2 FFT
  metadata.js              JPEG/PNG/WebP/HEIC/MP4/MOV/WebM parsers, EXIF, XMP, IPTC, ICC, C2PA/JUMBF/CBOR
  forensics.js             spectral, CFA, noise and JPEG-grid analysis
  forensics-worker.js      runs forensics.js off the main thread
  imageops.js              canvas helpers, heat-maps, error-level analysis
  neural.js                model loading (workers, cache, prefetch) and inference
  neural-worker.js         Web Worker that hosts one model
  evidence.js              turns measurements into explained signals
  calibration.js           all thresholds and weights
  fusion.js                combines signals into the verdict
  detector.js              the analysis pipeline
assets/js/ui/              interface
  components.js            gauge, comparison viewer + magnifier, lightbox, tooltip, toast
  explorer.js              landing-page "detection layers" explorer
  result.js                interactive report (score builder, lab, metadata explorer)
  app.js                   input, model preloading, live analysis view, verdict reveal, settings
tests/                     evaluation harness for re-calibration
```
